# Visual Bookmark 最终审核报告

## 第一轮：产品符合性

- 修正入口边界：明确使用扩展专属侧边栏，不修改 Chrome 原生书签侧边栏，不覆盖新标签页。
- 固化布局规则：视觉模式 `<280px` 一列，`>=280px` 两列，宽侧栏仍保持两列。
- 固化封面：可见区域截图中心裁切 16:10、最大 960px、WebP 0.78。
- 补齐管理能力：新建文件夹、编辑、移动、删除、标签、上传/清除/重新截取封面、批量操作。
- 补齐设置的真实行为：默认新标签打开和文件夹标签显隐均接入侧边栏。

结论：通过。

## 第二轮：工程与数据一致性

- 修复旧书签首次添加标签时没有元数据记录的问题。
- 修复更新重复书签但本次无截图时丢失旧封面引用的问题。
- 修复旧书签没有元数据时无法记录最近打开时间的问题。
- 重复 URL 检测改为遍历完整原生书签树，正确忽略 fragment。
- 删除书签与清理本地封面/元数据使用事务并有孤儿清扫兜底。
- 大型书签库使用 MiniSearch；卡片改用稳定的响应式网格，自动测试覆盖 10,000 条搜索、响应式列数和完整卡片渲染。

结论：通过。

## 第三轮：安全、权限与发布

- 网页访问是截图与批量补全公开预览图的核心权限，只在用户主动操作时使用。
- 截图改为侧边栏直接捕获，避免高分辨率 PNG 通过 runtime message 时丢失；失败不再静默降级为纯文字书签。
- 阻止 `javascript:`、`data:` 与 `vbscript:` 书签执行；自定义协议打开前二次确认。
- runtime message 使用字段级校验；页面数据只以 React 文本渲染。
- 生产 Manifest 无 Cookie、history 或远程代码权限。
- 生产依赖漏洞审计未发现已知漏洞。
- 真实 Chrome 151 无界面模式已加载生产目录；构建与测试通过。

结论：通过。发布者身份、邮箱、公开隐私政策 URL 和商店截图仍需在正式上架时填写。
